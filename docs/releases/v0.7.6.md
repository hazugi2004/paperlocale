# PaperLocale 0.7.6 — 2026-09-23

## 修复与行为

- 段落框边界附近的原文标点不再过早截断后续完整译文；若真正无法排入，错误直接指出 PDF 页码和剩余词元数，不会生成缺内容的候选 PDF。
- 新运行未指定 Provider 时，默认使用 `codex-local`、模型 `gpt-6-sol`、推理档位 `medium`。已有 Codex 断点从清单读取原模型和档位；显式指定仍可覆盖默认值，但必须符合现有断点的身份校验。
- 机器 QA 通过后，候选 PDF 默认复制到原 PDF 所在目录，命名为 `原文件名_translated_by_paperlocale.pdf`。运行目录仍保留完整候选、哈希、QA 报告与逐页对照。未知同名文件不会被覆盖；本运行旧导出只能在重新 QA 后更新。
- 等待式运行与直接退出式命令均在当前终端显示脱敏的错误原因、代码位置和针对性的解决办法；等待记录继续保存在 `waiting.json`，供程序恢复和审计。

## 验收边界

源文件及译文哈希、QA 报告必须一致才能导出。`qa_generated` 表示机器检查通过，人工仍须逐页检查并执行 `paperlocale accept`。默认输出文件名不表示人工已验收。

本地完整测试为 290 项通过。此前已人工验收的 Fu 等 2026 年论文运行目录在恢复清单所绑定的 PDF 后，使用此版本导出了同目录新命名 PDF；导出文件与原 QA 报告的 SHA-256 均为 `305bd48f0643e6710b7fc44d00f7263150e3c1ff72bcd03c0b8f47409a7ad48d`。这一步复用已验收译文，没有重新调用翻译模型。
