# PaperLocale v0.3.2

v0.3.2 把第二次真实论文试运行暴露的四类边界收敛为可审计、可复现的通用能力。
参考文献默认策略仍是 `preserve`；本版本没有用本地 PDF 覆盖或提示词猜测掩盖
上游版面对象问题。

## 主要变化

- 参考文献标题确定性支持单数或复数、可选章节号和投稿手稿边栏行号，例如
  `6 Reference 353`；参考文献区域止于下一个编号章节，避免把 Figure 图注误收；
- `passthrough_map.json` 绑定源 PDF、`segments.jsonl` 哈希和逐条人工确认信息。
  纯公式、作者姓名串等非正文片段只有在确认原因、确认人和时间均留档后才能原样
  写入，且必须严格 `target == source`；
- 部分批次失败后可以把尚未保存的失败片段确认成透传，继续复用同批其他合格
  译文，不会重复高成本模型调用；
- 翻译前从源 PDF 精确可见文本识别跨对象碎词和不可见短 ASCII 片段。
  `Figu + re…perio + d` 一类对象会写入哈希绑定的安全清单并阻止 Provider，直到
  用户显式确认透传；
- 运行清单升级到 schema 4，记录透传映射和片段安全摘要的路径、数量与 SHA-256；
- macOS CI 增加源码目录和虚拟环境都含中文与空格的非 editable 安装测试。

## 上游协作

真实 `preserve` 仍被 BabelDOC 的对象比较错误限制：`post_translate_paragraph`
把译文字符串与 `TranslateInput` 对象比较，因此同文返回仍会触发重排。项目已按
BabelDOC 贡献规范提交：

- [BabelDOC Issue #610](https://github.com/funstory-ai/BabelDOC/issues/610)；
- [BabelDOC PR #611](https://github.com/funstory-ai/BabelDOC/pull/611)：最小修复和
  一个对象身份回归测试。

本地测试为 1/1 通过，Ruff 通过。首次 fork 的上游 Actions 当前需要维护者批准
运行；这不是 PaperLocale 可以代替上游完成的合并或发布。本版本继续如实记录该
边界，不把 PR 写成已经生效的上游能力。

## 已知边界

- 在 BabelDOC #611 合并并发布前，参考文献 `target == source` 仍可能被上游重新
  排版；
- v0.3.2 对跨对象碎词采用安全透传，意味着该片段保持原文；完整翻译需要上游
  提供相邻对象上下文或合并能力；
- 机器 QA 的 0 errors / 0 warnings 不代表视觉完全正确，最终 PDF 仍必须逐页
  人工验收；
- 本版本继续固定到已验证的 `pdf2zh-next 2.9.x / BabelDOC 0.6.x` 兼容范围。
